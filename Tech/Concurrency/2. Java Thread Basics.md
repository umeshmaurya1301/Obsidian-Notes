### 1. The `Thread` Class

`java.lang.Thread` is a concrete class that represents an independent path of execution in your program. When you create a `Thread` object, you are creating a new lifecycle that can be started, paused, interrupted, or stopped.

**How to use it:**

You create a new class that extends `Thread` and override its `run()` method. The `run()` method contains the code you want to execute concurrently. To kick it off, you instantiate your class and call the `start()` method (never call `run()` directly, or it will execute on the current thread, defeating the purpose!).

**Example:**

Java

```
// 1. Extend the Thread class
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Worker thread is running: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        // 2. Instantiate and start
        MyThread t1 = new MyThread();
        t1.start(); // This spawns a new OS thread and calls run()
        
        System.out.println("Main thread is running: " + Thread.currentThread().getName());
    }
}
```

**Pros & Cons:**

- **Pros:** Very straightforward for simple, quick-and-dirty scripts. You can directly access thread methods like `this.getName()` or `this.interrupt()` inside the `run()` method.
    
- **Cons (The Catch):** Java does not support multiple inheritance. If your class extends `Thread`, it **cannot extend any other class**. This severely limits your object-oriented design. It also tightly couples the "Task" with the "Runner", which is considered poor design in modern software engineering.

### 2. The `Runnable` Interface

`java.lang.Runnable` is a functional interface (an interface with only one method). It represents a task that is intended to be executed by a thread. It has a single abstract method: `public void run()`.

**How to use it:**

You create a class that implements `Runnable` and provide the logic inside the `run()` method. Because a `Runnable` is just a "job," it cannot run itself. You must create a `Thread` (the worker), hand the `Runnable` to it via its constructor, and then start the `Thread`.

**Example:**

Java

```
// 1. Implement the Runnable interface
class MyJob implements Runnable {
    @Override
    public void run() {
        System.out.println("Job is being executed by: " + Thread.currentThread().getName());
    }
}

public class Main {
    public static void main(String[] args) {
        // 2. Instantiate the job
        MyJob myJob = new MyJob();
        
        // 3. Hand the job to a new Thread and start it
        Thread worker = new Thread(myJob);
        worker.start();
    }
}
```

_Note: Because `Runnable` is a functional interface, you can also use lambda expressions to create them instantly:_

Java

```
Thread lambdaWorker = new Thread(() -> System.out.println("Lambda job running!"));
lambdaWorker.start();
```

**Pros & Cons:**

- **Pros:** This is the highly recommended approach. It separates the task logic (`Runnable`) from the execution mechanism (`Thread`). Because you are only implementing an interface, your class is **free to extend another class** if needed. It also makes your jobs reusable and easily passable to modern Java concurrency tools like `ExecutorService`.
    
- **Cons:** Slightly more verbose since you have to instantiate both the task and the thread (though lambdas largely fix this).

### Summary Comparison

|**Feature**|**Thread (Class)**|**Runnable (Interface)**|
|---|---|---|
|**Concept**|The Worker|The Job / Task|
|**Inheritance**|Cannot extend any other class.|Can extend another class.|
|**Coupling**|Tightly couples task and execution.|Decouples the task from how it is executed.|
|**Reusability**|A `Thread` instance cannot be restarted once it finishes.|A `Runnable` instance can be passed to multiple threads or thread pools.|
|**Modern Java**|Rarely used directly in enterprise code.|Heavily used (often passed to `ExecutorService`).|
