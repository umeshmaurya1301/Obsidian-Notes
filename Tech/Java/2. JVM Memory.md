# 57. Reachability Analysis

This is the fundamental GC algorithm.

Many beginners think:

```text
Reference Count = 0
→ Collect
```

Java does **not** use reference counting.

---

Example:

```java
User u1 = new User();
User u2 = u1;

u1 = null;
u2 = null;
```

Now:

```text
User Object
```

has no references.

Eligible for GC.

---

But consider:

```java
class A {
    B b;
}

class B {
    A a;
}
```

```java
A a = new A();
B b = new B();

a.b = b;
b.a = a;

a = null;
b = null;
```

Memory:

```text
A <----> B
```

Reference counting would fail:

```text
A has reference from B
B has reference from A
```

count ≠ 0

---

Java instead asks:

> Can I reach this object from a GC Root?

If yes:

```text
Keep it
```

If no:

```text
Collect it
```

---

# 58. GC Roots

GC starts traversal from special roots.

Think of them as:

```text
Known live starting points
```

---

## Common GC Roots

### 1. Thread Stack Variables

```java
void process() {
    User user = new User();
}
```

```text
Thread Stack
    ↓
user
    ↓
User Object
```

---

### 2. Static Variables

```java
static User user = new User();
```

```text
Static Field
    ↓
User Object
```

---

### 3. Active Threads

```java
new Thread(...)
```

Running threads are roots.

---

### 4. JNI References

Native code references.

---

## Example

```java
User u = new User();
Order o = new Order();

u.order = o;
```

Graph:

```text
GC Root
   ↓
User
   ↓
Order
```

Both survive.

---

Remove:

```java
u = null;
```

Now:

```text
User
 ↓
Order
```

No path from GC Root.

Both collected.

---

### Interview Answer

GC Roots are special objects from which the JVM starts reachability analysis.

---

# 59. Minor GC

Most frequent GC.

Works on:

```text
Young Generation
```

only.

---

Before GC:

```text
Eden

A
B
C
D
E
```

Suppose:

```text
A dead
B alive
C dead
D alive
E dead
```

Minor GC:

```text
S0

B(age=1)
D(age=1)
```

---

Dead objects removed.

Alive objects copied.

---

Characteristics:

```text
Fast
Frequent
Young Gen Only
```

---

### Interview Question

Why is Minor GC fast?

Because most objects die young.

---

# 60. Major GC

Works on:

```text
Old Generation
```

---

Old Gen contains:

```text
Cache
Singletons
Long-lived objects
```

---

Scanning Old Gen is expensive.

Example:

```text
Old Gen = 8 GB
```

Major GC must inspect large object graphs.

---

Characteristics:

```text
Less Frequent
More Expensive
```

---

### Important

Different collectors define Major GC differently.

Interview-wise:

> Major GC primarily targets Old Generation.

is enough.

---

# 61. Full GC

Most expensive GC.

---

Scans:

```text
Young Generation
Old Generation
Metaspace (sometimes involved)
```

Entire JVM memory.

---

Typical trigger:

```text
Old Generation Full
```

or

```text
Explicit System.gc()
```

or

```text
Metadata pressure
```

---

Example log:

```text
Full GC (Allocation Failure)
```

---

Characteristics:

```text
Slow
Expensive
Avoid in production
```

---

### Interview Answer

Full GC performs collection across the entire heap and is usually the most expensive GC event.

---

# 62. Stop-The-World (STW)

One of the most important concepts.

---

When GC runs:

```text
Application Threads
```

often must pause.

---

Example:

```text
Thread-1
Thread-2
Thread-3
```

All stopped.

---

GC executes:

```text
Reachability Analysis
Object Movement
Cleanup
```

---

Then:

```text
Threads Resume
```

---

Visualization:

```text
Running
Running
Running

PAUSE

GC

Resume
Resume
Resume
```

---

Why pause?

Imagine:

```java
user.address.city
```

changing while GC scans memory.

GC could see inconsistent state.

---

### Impact

If pause:

```text
50 ms
```

users won't notice.

If pause:

```text
10 seconds
```

production outage.

---

### Interview Answer

Stop-The-World is a pause during which application threads are suspended so the garbage collector can safely perform memory management.

---

# 63. G1 GC

Most important collector today.

Default in modern JVMs.

---

G1 means:

```text
Garbage First
```

---

Older collectors:

```text
Young Gen
Old Gen
```

large contiguous regions.

---

G1 divides heap into many small regions.

---

Instead of:

```text
Heap

Young
Old
```

G1:

```text
[R][R][R][R][R]
[R][R][R][R][R]
[R][R][R][R][R]
```

Many regions.

---

Each region may contain:

```text
Young
Survivor
Old
```

objects.

---

## Why "Garbage First"?

G1 tracks:

```text
Live Data %
Garbage %
```

per region.

---

Example:

```text
Region A → 90% garbage
Region B → 80% garbage
Region C → 5% garbage
```

G1 cleans:

```text
A first
B second
```

Maximum benefit.

---

Hence:

```text
Garbage First
```

---

## Goal

Predictable pauses.

You can configure:

```bash
-XX:MaxGCPauseMillis=200
```

Meaning:

```text
Try to keep pauses around 200ms
```

(not guaranteed)

---

## Why Companies Like It

Good for:

```text
2 GB
4 GB
8 GB
16 GB
32 GB
```

heaps.

Balances:

```text
Throughput
Latency
Memory Usage
```

---

### Interview Answer

G1 GC divides the heap into regions and prioritizes collecting regions with the most reclaimable garbage, aiming for predictable pause times.

---

# 64. ZGC

Designed for:

```text
Huge Heaps
```

Example:

```text
128 GB
256 GB
1 TB
```

---

Goal:

```text
Extremely Low Pause Times
```

Typically:

```text
< 1 ms
to
a few ms
```

even with huge heaps.

---

How?

Most work happens:

```text
Concurrently
```

while application continues running.

---

### Use Cases

Large-scale:

* Trading systems
* Databases
* Massive backend services

---

### Interview Answer

ZGC is a low-latency collector designed for very large heaps with minimal pause times.

---

# 65. Shenandoah

Red Hat collector.

Similar philosophy:

```text
Low Pause
Concurrent Work
```

---

Goal:

```text
Pause time independent of heap size
```

---

Example:

```text
8 GB heap
64 GB heap
128 GB heap
```

Pause remains relatively small.

---

### Interview Answer

Shenandoah is a low-pause collector that performs much of its work concurrently with application threads.

---

# 66. GC Tuning Basics

Most interviewers don't expect deep tuning.

Know the basics.

---

## Heap Size

```bash
-Xms2g
-Xmx2g
```

Initial and maximum heap.

---

## GC Logging

Modern JVM:

```bash
-Xlog:gc*
```

Shows:

```text
GC Events
Pause Times
Heap Usage
```

---

## G1 Pause Goal

```bash
-XX:MaxGCPauseMillis=200
```

Target pause time.

---

## Metaspace Limit

```bash
-XX:MaxMetaspaceSize=512m
```

---

## Common Metrics

Monitor:

```text
GC Frequency
Pause Time
Heap Utilization
Old Gen Growth
```
