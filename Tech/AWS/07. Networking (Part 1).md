# Lecture 7 – AWS Networking (Part 1)

> [!info] Overview
> Networking foundations before diving into AWS **VPC**. Covers how devices find and talk to each other: **networks**, **switches** (MAC / Layer 2) vs **routers** (IP / Layer 3), **IPv4 vs IPv6**, **public vs private** addressing, **CIDR** notation, **routing tables**, and how **NAT** lets many private devices share one public IP. Ends by tracing a packet's full journey — and mapping each piece to its AWS equivalent (**NAT Gateway**, **Internet Gateway**).

---

## 🎯 Key Concepts

### Network & Router
- A **network** = a group of interconnected devices that can exchange data (your home Wi-Fi, an office LAN, a `VPC`).
- A **router** forwards data **between different networks** — it's the device that connects your local network to the internet. Operates at **Layer 3** using **IP addresses**, and decides *where to send a packet next* via its **routing table**.

### Switch vs Router — MAC vs IP
The two are constantly confused; the clean split is **inside a network vs between networks**.

| | **Switch** | **Router** |
|---|---|---|
| Layer | **L2** (Data Link) | **L3** (Network) |
| Addresses | **MAC** | **IP** |
| Scope | *Within* one network (LAN) | *Between* networks |
| Lookup table | MAC address table (CAM) | Routing table |

- **MAC address** — a **48-bit** hardware ID burned into the NIC, written as 6 hex octets (`00:1A:2B:3C:4D:5E`). Globally unique, doesn't change, used for **local delivery** within a LAN.
- **IP address** — a **logical** address used for **end-to-end routing across networks**; can change (e.g. DHCP).
- They cooperate: to deliver inside a subnet, a device resolves the target **IP → MAC** via **`ARP`**, then the switch forwards the frame by MAC. To leave the subnet, the frame is addressed to the **router's MAC** (the default gateway), and the router takes over by IP.

### IP Address — IPv4 vs IPv6
| | **IPv4** | **IPv6** |
|---|---|---|
| Size | **32-bit** | **128-bit** |
| Format | Dotted decimal — `192.168.1.1` | 8 hex groups — `2001:db8:85a3::8a2e:370:7334` |
| Space | `2³²` ≈ **4.3 billion** | `2¹²⁸` ≈ **3.4 × 10³⁸** |

- IPv4 = four **octets** (0–255), 8 bits each → 32 bits total.
- IPv6 fixes exhaustion outright with a practically unlimited space; `::` collapses one run of consecutive zero-groups.

### Public vs Private IP (why IPv4 hasn't "run out")
- Only **~4.3 billion** IPv4 addresses exist — far fewer than today's connected devices. So how does the internet still work?
- **Private IPs + NAT.** Most devices use **private** addresses that are **reused independently by every network** (your `192.168.1.10` and your neighbour's never clash — they never appear on the public internet). A whole home/office shares just **one (or a few) public IPs** via **NAT**, collapsing demand for the scarce public pool.
- **What makes an IP "private":** it falls inside the **RFC 1918** reserved ranges. Public routers are configured to **drop** packets with private source/destination addresses — they are only meaningful *inside* a local network.

> [!example] RFC 1918 private ranges
> | CIDR | Address span | Size | Class |
> |---|---|---|---|
> | `10.0.0.0/8` | `10.0.0.0 – 10.255.255.255` | ~16.7M | A |
> | `172.16.0.0/12` | `172.16.0.0 – 172.31.255.255` | ~1M | B |
> | `192.168.0.0/16` | `192.168.0.0 – 192.168.255.255` | ~65K | C |
>
> (Also reserved: `127.0.0.0/8` loopback, `169.254.0.0/16` link-local.)

### CIDR — reading the `/prefix`
- **CIDR** = **Classless Inter-Domain Routing.** Notation `IP/prefix`, where **prefix = number of bits fixed as the *network* portion**; the rest are **host** bits.
- **Formula:** number of addresses = **`2^(32 − prefix)`**. Smaller prefix → bigger network.

| CIDR | Host bits | Total addresses | Usable (general)* |
|---|---|---|---|
| `/8` | 24 | 16,777,216 | 16,777,214 |
| `/16` | 16 | 65,536 | 65,534 |
| `/24` | 8 | 256 | 254 |
| `/28` | 4 | 16 | 14 |
| `/32` | 0 | 1 | single host |

> \*Usable = total − 2 (network + broadcast address). **AWS reserves 5 per subnet** (see Gotchas), so an AWS `/24` gives **251**, not 254.

- Reading `192.168.1.0/24`: first **24 bits** (`192.168.1`) are the network, last **8 bits** are the host → covers `192.168.1.0 – 192.168.1.255`.

### Routing Table & Hopping
- A **routing table** maps **destination CIDR → next hop / outgoing interface**. Every router has one.
- **Longest-prefix match:** when several routes match, the **most specific** (longest prefix) wins.
- **Default route `0.0.0.0/0`** = "everything not matched above → send to the default gateway" (toward the internet).

| Destination | Next hop |
|---|---|
| `192.168.1.0/24` | **Local** (directly connected) |
| `0.0.0.0/0` | `203.0.113.1` (ISP gateway) — default |

- **Hopping:** no single router knows the whole path. Each one makes a **local next-hop decision**, forwards the packet, and **decrements its TTL** by 1. At **TTL = 0** the packet is dropped and an `ICMP Time Exceeded` is returned — this prevents infinite loops and is exactly how **`traceroute`** discovers each hop.

### NAT (Network Address Translation)
- A **specialized router function** that rewrites a **private IP → public IP** (and back), letting many private devices share one public IP.
- The common form is **PAT / NAT-overload**: it disambiguates devices by **port number**, tracked in a **NAT translation table** (mechanics in the next section).

## 🛠️ How It Works — Connect the Dots

A packet's journey from a private device to the internet and back, naming each component in order:

```
[Device]            [Switch]          [Router + NAT]            [Internet]        [Server]
192.168.1.10  ─►   forwards by  ─►   1. routing table:     ─►  public  ─►   93.184.216.34:443
 (private IP)        MAC (L2)          dst not local →          internet       (public IP)
                                       default route 0.0.0.0/0
                                     2. NAT: rewrite src
                                       192.168.1.10:50000
                                       → 203.0.113.5:61000
        ◄───────────────────────────  reply to 203.0.113.5:61000  ◄──────────────┘
                                     3. NAT lookup port 61000
                                       → restore 192.168.1.10:50000
                                       → deliver to the exact device
```

**Step by step**
1. Device wants `93.184.216.34:443`. It's **not local**, so the frame is sent (by **MAC**, via the **switch**) to the **router** (default gateway).
2. The **router** consults its **routing table** → no specific match → **default route `0.0.0.0/0`** → out to the ISP/internet.
3. **NAT** rewrites the **source** `192.168.1.10:50000` → `203.0.113.5:61000` (its public IP + a unique port) and records the mapping.
4. The server only ever sees the **public IP**, and replies to `203.0.113.5:61000`.
5. On return, **NAT looks up port `61000`** in its table → maps back to `192.168.1.10:50000` → rewrites the destination → delivers to the **exact originating device**.

> [!example] One public IP, many devices — the NAT table
> The **port** is the key that tells return traffic apart. Even when two devices pick the *same* private source port, NAT assigns *different* public ports:
>
> | Inside (private) | ↔ Outside (public) | Destination |
> |---|---|---|
> | `192.168.1.10:50000` | `203.0.113.5:61000` | `93.184.216.34:443` |
> | `192.168.1.11:50000` | `203.0.113.5:61001` | `93.184.216.34:443` |
>
> Reply to `:61000` → device `.10`; reply to `:61001` → device `.11`. **One public IP + many ports → many private devices.**

### Mapping it to AWS
The same primitives, as managed AWS components ("specialized routers"):

| General networking | AWS equivalent |
|---|---|
| Private IP block | **VPC / subnet CIDR** (e.g. `10.0.0.0/16`) |
| Routing table | **VPC Route Table** (attached per subnet) |
| Router at the network edge | **Internet Gateway (IGW)** — the VPC's door to the internet |
| Home NAT router | **NAT Gateway** — outbound-only internet for private subnets |

- **Internet Gateway (IGW):** attaches to a **VPC**; **horizontally scaled, redundant, highly available** (no bandwidth bottleneck). Enables internet access for resources **with a public IP**, performing **1:1 NAT** between an instance's **private IPv4 ↔ public/Elastic IP**. A subnet is "public" precisely when its route table has a `0.0.0.0/0` route to an IGW.
- **NAT Gateway:** lives in a **public subnet** and lets instances in **private subnets** initiate **outbound** connections (OS/package updates, API calls) while staying **unreachable from the internet** — the managed version of home-router NAT (PAT).

## ⚠️ Gotchas & Limits
> [!warning]
> - **Switch ≠ Router.** Switch = L2/MAC *within* a network; Router = L3/IP *between* networks. Mixing these up is a classic slip.
> - **Smaller prefix = bigger network.** `/16` is *larger* than `/24`. It trips people up because the number is bigger but the network is smaller.
> - **AWS reserves 5 IPs per subnet**, not 2: `.0` network, `.1` VPC router, `.2` DNS, `.3` future use, and the **last** address (broadcast). So a `/24` subnet yields **251** usable hosts.
> - **Private IPs aren't internet-routable** — public routers drop them. They only work behind NAT.
> - **NAT is outbound-initiated.** A plain NAT/NAT-Gateway lets devices reach *out*; the internet can't open a connection *in* unless you explicitly map a port / put a public IP + IGW in front.
> - **IGW vs NAT Gateway:** IGW = bidirectional for **public-IP** resources (1:1 NAT); NAT Gateway = **outbound-only** for **private** resources (many:1 PAT). Don't conflate them.

## 🔑 Key Takeaways
- **Switch = MAC/L2 (inside a network); Router = IP/L3 (between networks).** `ARP` bridges IP → MAC locally.
- **IPv4 = 32-bit (~4.3B); IPv6 = 128-bit (~3.4×10³⁸).** IPv4 survives only because of **private addressing + NAT**.
- **Private ranges (RFC 1918):** `10/8`, `172.16/12`, `192.168/16` — reused per-network, never seen on the public internet.
- **CIDR:** addresses = `2^(32 − prefix)`; the prefix counts **network** bits.
- **Routing table** = destination CIDR → next hop, chosen by **longest-prefix match**, with `0.0.0.0/0` as the default route. Packets **hop** router-to-router, TTL−1 each hop.
- **NAT** shares one public IP across many devices, disambiguating return traffic by **port**.
- **AWS mapping:** VPC CIDR · Route Table · **Internet Gateway** (public, 1:1) · **NAT Gateway** (private, outbound-only).

## 🎤 Interview Tips
- Nail the **L2 vs L3 / switch vs router / MAC vs IP** distinction — a frequent fundamentals checkpoint.
- Be ready to compute subnet sizes from CIDR on the spot (`2^(32 − prefix)`), and know the **AWS "5 reserved IPs"** quirk — it shows hands-on VPC experience.
- "How do thousands of devices share one public IP?" → **NAT/PAT keyed on port numbers** + the translation table. A crisp story here lands well.
- For AWS: "public subnet vs private subnet" → **public = route to an Internet Gateway**; **private = no IGW route, outbound via a NAT Gateway**. Distinguishing **IGW (1:1, bidirectional)** from **NAT Gateway (many:1, outbound-only)** is a common VPC question.
