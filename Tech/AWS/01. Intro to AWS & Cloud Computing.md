# Lecture 1 – Intro to AWS & Cloud Computing

> [!info] Overview
> Cloud computing is renting computing resources (servers, storage, databases, networking) over the internet on a pay-as-you-go basis instead of owning physical hardware. **AWS (Amazon Web Services)** is the market-leading cloud provider, offering 200+ on-demand services. This lecture covers what the cloud is, why it matters, and the standard service models — `IaaS`, `PaaS`, `CaaS`, `FaaS`, `SaaS`.

---

## 🎯 Key Concepts

### What is Cloud Computing?
- On-demand delivery of IT resources over the internet, billed for what you use.
- Replaces upfront **CapEx** (buying servers) with variable **OpEx** (renting capacity).
- Core benefits:
  - **Elasticity** — scale up/down with demand, no over-provisioning.
  - **Pay-as-you-go** — no idle hardware cost.
  - **Global reach** — deploy near users via worldwide data centers.
  - **No maintenance** — provider handles hardware, power, cooling, security patching.

### What is AWS?
- Amazon's cloud platform, launched **2006**, the largest provider by market share.
- Resources live in **Regions** (geographic areas, e.g. `us-east-1`) made of **Availability Zones (AZs)** — isolated data centers for fault tolerance.
- You access services via the **Console** (web UI), **CLI**, or **SDKs**.
- Examples: `EC2` (servers), `S3` (storage), `RDS` (databases), `Lambda` (functions).

---

## 🛠️ Cloud Service Models

The models differ by **how much you manage vs. how much the provider manages**. Less management = less control but faster delivery.

### `IaaS` — Infrastructure as a Service
- You rent raw infrastructure: virtual machines, storage, networking.
- **You manage:** OS, runtime, apps, data. **Provider manages:** physical hardware, virtualization.
- AWS example: **`EC2`**, `VPC`, `EBS`.
- Analogy: renting an empty plot of land — you build the house.

### `PaaS` — Platform as a Service
- Provider gives a ready platform (OS + runtime); you just deploy code.
- **You manage:** app + data only. **Provider manages:** OS, runtime, scaling.
- AWS example: **`Elastic Beanstalk`**, `App Runner`.
- Analogy: renting a furnished apartment — just move in.

### `CaaS` — Containers as a Service
- Run and orchestrate **containers** without managing the host VMs.
- AWS example: **`ECS`**, **`EKS`** (Kubernetes), `Fargate` (serverless containers).
- Sits between `IaaS` and `PaaS`; good for microservices.

### `FaaS` — Functions as a Service (Serverless)
- Run individual functions triggered by events; no servers to manage at all.
- Billed per execution / per ms — scales to zero when idle.
- AWS example: **`Lambda`**.
- Analogy: hire a contractor only when there's a specific task.

### `SaaS` — Software as a Service
- Fully built software delivered over the internet; you just use it.
- **Provider manages everything.** You manage only your data/config.
- Examples: Gmail, Salesforce, Dropbox; AWS example: `WorkMail`, `Chime`.

> [!example] The "pizza as a service" mental model
> - **On-premise:** make pizza at home (you buy/manage everything).
> - **`IaaS`:** buy frozen pizza, bake it yourself (provider gives base infra).
> - **`PaaS`:** order delivery (you provide the table/drinks = app + data).
> - **`SaaS`:** eat at the restaurant (everything is handled).

---

## ⚠️ Gotchas & Limits
> [!warning]
> - Control vs. convenience is a **trade-off** — `IaaS` = most control + most ops work; `SaaS` = least control + least work.
> - **Serverless ≠ no servers** — servers exist, AWS just manages them invisibly (`FaaS`).
> - Pay-as-you-go can surprise you: idle-but-running `EC2` instances and forgotten storage still bill. Always tear down test resources.
> - `CaaS` and `FaaS` are sometimes grouped under broader "serverless"; the boundaries aren't rigid.

---

## 🔑 Key Takeaways
- Cloud = renting IT resources on-demand, pay only for what you use.
- AWS is the largest cloud provider; resources organized into **Regions → AZs**.
- The spectrum of control: `IaaS` → `CaaS` → `PaaS` → `FaaS` → `SaaS` (you manage progressively less).
- Memorize one AWS service per model: `EC2` (IaaS), `Beanstalk` (PaaS), `ECS/EKS` (CaaS), `Lambda` (FaaS), `WorkMail` (SaaS).

---

## 🎤 Interview Tips
- A common warm-up: *"What's the difference between IaaS, PaaS, and SaaS?"* — anchor your answer on **who manages what** (the shared-responsibility split).
- For system design, know **why** you'd pick a model: `Lambda` for spiky/event-driven workloads, `EC2` for full control / long-running processes, `Fargate` to run containers without managing nodes.
- Mention **Regions & AZs** when discussing high availability — multi-AZ deployment is the baseline answer for fault tolerance.
