## 🧠 The one diagram to hold in your head

Everything in these notes hangs off this:

```text
Request
   |
   v
DelegatingFilterProxy  ->  FilterChainProxy  ->  SecurityFilterChain
   |
   v
Authentication Filter                     [note 1, 5, 7, 8]
   |   form login / HTTP basic / JWT / bearer token
   |
   v
AuthenticationManager                     [note 2]
   |   -> AuthenticationProvider
   |        -> UserDetailsService  (load the user)
   |        -> PasswordEncoder     (verify the password)  [note 3]
   |
   v
Authentication  ->  SecurityContextHolder [note 4]
   |   Principal + Credentials + Authorities + authenticated
   |
   v
AuthorizationFilter                       [note 6]
   |   hasRole / hasAuthority / permitAll
   |
   v
DispatcherServlet  ->  Controller
   |
   v
@PreAuthorize on the service              [note 6]
```

**Authentication filters *write* to `SecurityContextHolder`; authorization *reads* from it.** Every topic — form login, JWT, OAuth2, method security — is a variation on which filter does the writing.

## ⚡ The ten answers worth memorising

| Question | Answer |
|---|---|
| What is a `SecurityFilterChain`? | An ordered list of security filters + a matcher; only the first matching chain runs |
| Who verifies the password? | `AuthenticationProvider` + `PasswordEncoder` — **not** `UserDetailsService` |
| Why can't you compare BCrypt hashes with `equals`? | New random salt every `encode()` → use `matches()` |
| Where is the current user stored? | `SecurityContextHolder` → `SecurityContext` → `Authentication`, in a **`ThreadLocal`** |
| `hasRole("ADMIN")` vs `hasAuthority("ROLE_ADMIN")` | Identical — `hasRole` just prepends `ROLE_` |
| 401 vs 403 | 401 = not authenticated · 403 = authenticated but not permitted |
| OAuth2 vs JWT | Protocol vs token format — OAuth2 may issue opaque tokens instead |
| Why an authorization code, not a token, in the redirect? | The redirect goes through the browser (URL, history, logs); the code is single-use and useless alone |
| How do you log out with JWT? | You can't, statelessly — short expiry + `jti` denylist + revoke the refresh token |
| When can you disable CSRF? | Only when credentials aren't attached automatically, i.e. header-based `Bearer` tokens |
