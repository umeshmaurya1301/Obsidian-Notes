# 🧩 1. @Test Annotation

`@Test` marks a method as a test case.

### Example
class CalculatorTest {

    @Test
    void shouldAddTwoNumbers() {
        Calculator calculator = new Calculator();
        int result = calculator.add(2, 3);

        assertEquals(5, result);
    }
}

### Key Points
- Test methods are usually `void`
- No parameters required
- No need to make them `public`
- Never call test methods manually

# 🧩 2. Assertions

Assertions verify expected vs actual results.

---

## 🔹 Common Assertions

### assertEquals
assertEquals(5, calculator.add(2, 3));

### assertTrue
assertTrue(user.isActive());

### assertFalse
assertFalse(order.isCancelled());

### assertNull
assertNull(user.getMiddleName());

### assertNotNull
assertNotNull(user);

---

## 🔹 Exception Testing

### assertThrows
assertThrows(IllegalArgumentException.class, () -> {
    calculator.divide(10, 0);
});

👉 Used to verify exception scenarios

---

## 🔹 Multiple Assertions

### assertAll
assertAll(
    () -> assertNotNull(user),
    () -> assertEquals("Umesh", user.getName()),
    () -> assertEquals("umesh@gmail.com", user.getEmail())
);

---

## 🔹 No Exception Case

### assertDoesNotThrow
assertDoesNotThrow(() -> calculator.add(2, 3));

---

## 🔹 Testing Pattern (AAA)

- Arrange → setup data
- Act → call method
- Assert → verify result

---

# 🧩 3. Lifecycle Annotations

Used to run setup/cleanup logic.

---

## 🔹 @BeforeEach

Runs before every test

@BeforeEach
void setUp() {
    calculator = new Calculator();
}

---

## 🔹 @AfterEach

Runs after every test

@AfterEach
void tearDown() {
    calculator = null;
}

---

## 🔹 @BeforeAll

Runs once before all tests

@BeforeAll
static void initAll() {
    System.out.println("Before all tests");
}

👉 Usually must be static

---

## 🔹 @AfterAll

Runs once after all tests

@AfterAll
static void cleanupAll() {
    System.out.println("After all tests");
}

---

## 🔹 Execution Order

1. @BeforeAll
2. @BeforeEach
3. @Test
4. @AfterEach
5. @AfterAll

---

# 🧩 4. Assumptions

Used to skip tests based on conditions.

---

## 🔹 assumeTrue

assumeTrue("dev".equals(System.getProperty("env")));

---

## 🔹 assumeFalse

assumeFalse("prod".equals(System.getProperty("env")));

---

## 🔹 Difference: Assertion vs Assumption

- Assertion → fails test if condition false
- Assumption → skips test if condition false

---

## 🔹 Use Cases

- Environment-based testing
- OS-specific logic
- External dependency availability

---

# 🧩 5. Full Example

class CalculatorTest {

    private Calculator calculator;

    @BeforeAll
    static void beforeAll() {
        System.out.println("Before all tests");
    }

    @BeforeEach
    void setUp() {
        calculator = new Calculator();
    }

    @Test
    void shouldAddNumbers() {
        assertEquals(5, calculator.add(2, 3));
    }

    @Test
    void shouldThrowExceptionWhenDividingByZero() {
        assertThrows(ArithmeticException.class, () -> calculator.divide(10, 0));
    }

    @AfterEach
    void tearDown() {
        calculator = null;
    }

    @AfterAll
    static void afterAll() {
        System.out.println("After all tests");
    }
}

# ⚠️ Common Mistakes

❌ Only testing happy path  
❌ Using print instead of assertions  
❌ Writing large test methods  
❌ Ignoring exception cases  
❌ Not using setup methods
