## 📌 1. Introduction

Mockito is the most popular **mocking framework for Java**. It is used in unit testing to create test doubles (fake objects) and isolate dependencies so you can test your business logic in a controlled environment.

### 🎯 Why Mockito?

- **Speed:** Avoid slow database, API, or Kafka network calls.
    
- **Reliability:** Tests won't fail due to external system outages.
    
- **Isolation:** Pinpoint bugs precisely by only testing one class at a time.
    
- **Behavior-Based Testing:** Verify that specific methods were called with the correct arguments.
    

---

## 🧠 2. The Core Idea (Isolate the Target)

In unit testing, you should test **only one class** at a time. All of its external dependencies should be mocked.

**Example Architecture:** `Controller` → `Service` → `Repository` → `Database`

👉 **If testing the `Service`:**

- Mock the `Repository`.
    
- Test _only_ the `Service` logic.
    
- Do not load the Database or the Controller.
    

---

## ⚙️ 3. Project Setup (JUnit 5)

To enable Mockito annotations in JUnit 5, you must annotate your test class with the Mockito extension.

Java

```
@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    // Tests go here
}
```

---

## 🧩 4. Core Annotations

### 🔹 `@Mock`

Creates a complete fake instance of a class or interface.

Java

```
@Mock
UserRepository userRepository;
```

### 🔹 `@InjectMocks`

Creates the instance of the class you are actually testing and automatically injects the `@Mock` fields into it. Mockito tries to inject by (in order): Constructor, Setter, Field reflection.

Java

```
@InjectMocks
UserService userService;
```

### 🔹 `@Spy`

Creates a partial mock. By default, it calls the _real_ methods of the object unless you explicitly stub them.

Java

```
@Spy
List<String> list = new ArrayList<>();
```

### 🔹 `@Captor`

Creates an `ArgumentCaptor` to inspect the exact values passed to a mock during a method call.

Java

```
@Captor
ArgumentCaptor<User> userCaptor;
```

---

## 🔥 5. Test Doubles: Mock vs Stub vs Spy

|**Type**|**Uses Real Object?**|**Behavior**|**Typical Use Case**|
|---|---|---|---|
|**Mock**|❌ No|Completely fake. Returns null/empty by default.|External dependencies (DBs, APIs).|
|**Stub**|❌ No|A mock with pre-programmed, fixed responses.|When your logic depends on a return value.|
|**Spy**|✅ Yes|Wraps a real object. Can override specific methods.|Legacy code, or testing specific utility classes.|

## 🧪 6. Stubbing (Controlling Behavior)

### Classic Mockito (`when` / `thenReturn`)

Java

```
// Return a value
when(repo.findById(1L)).thenReturn(Optional.of(user));

// Throw an exception
when(repo.findById(1L)).thenThrow(new EntityNotFoundException());

// Custom logic based on input (Advanced)
when(repo.findById(anyLong())).thenAnswer(invocation -> {
    Long id = invocation.getArgument(0);
    return Optional.of(new User(id));
});
```

### BDD Mockito (Modern approach: Given / When / Then)

Many modern teams prefer `BDDMockito` because it reads more naturally.

Java

```
given(repo.findById(1L)).willReturn(Optional.of(user));
```

## 🔍 7. Verifying Interactions

Verification ensures your code actually called the dependency exactly as expected.

Java

```
// Basic (Default is 1 time)
verify(repo).findById(1L);

// Exact number of times
verify(repo, times(2)).findById(1L);

// Never called
verify(repo, never()).delete(any());

// At least/At most
verify(repo, atLeastOnce()).save(any());
verify(repo, atMost(3)).save(any());
```

---

## 🧠 8. Argument Matchers

Matchers allow you to stub or verify methods without knowing the exact arguments.

**Common Matchers:** `any()`, `anyString()`, `anyLong()`, `anyInt()`, `eq(value)`

Java

```
when(repo.findById(anyLong())).thenReturn(Optional.of(user));
```

⚠️ **The Golden Rule of Matchers:**

If a method takes multiple arguments, and you use a matcher for _one_, you **must** use matchers for _all_ of them.

Java

```
// ❌ WRONG: Will throw an exception
when(service.process(1L, anyString())).thenReturn(true);

// ✅ CORRECT: Use eq() for specific values alongside matchers
when(service.process(eq(1L), anyString())).thenReturn(true);
```

---

## 🎯 9. ArgumentCaptor (Inspect the Input)

Used during verification to capture the exact object passed into a mock, so you can run assertions on its internal state.

Java

```
// 1. Act
userService.registerUser("Umesh", "password123");

// 2. Capture
verify(repo).save(userCaptor.capture());

// 3. Assert
User savedUser = userCaptor.getValue();
assertEquals("Umesh", savedUser.getName());
assertNotNull(savedUser.getCreatedAt());
```

---

## ⚡ 10. Working with Spies (Partial Mocks)

Spies execute real code unless overridden. Because of this, you must use `doReturn` instead of `when.thenReturn`.

Java

```
List<String> list = spy(new ArrayList<>());
list.add("A"); // Calls real method

// ❌ AVOID: This will execute the real size() method before stubbing it!
when(list.size()).thenReturn(100);

// ✅ USE: This safely stubs the method without executing the real one.
doReturn(100).when(list).size();
```

---

## 🧩 11. Testing Void Methods

You cannot use `when()` on void methods because they return nothing. You must use the `doFamily` of methods.

Java

```
// Throw exception on void method
doThrow(new RuntimeException()).when(emailService).sendEmail(any());

// Do nothing (default for mocks, but useful for Spies)
doNothing().when(emailService).sendEmail(any());
```

---

## ⚠️ 12. Strict Stubbing & Lenient

JUnit 5 Mockito is **strict**. If you stub a method but your test never calls it, Mockito will throw an `UnnecessaryStubbingException`. If you intentionally need a stub that might not be used, mark it as lenient.

Java

```
lenient().when(repo.findById(1L)).thenReturn(user);
```

## 🌟 13. Advanced Additions for Backend Devs

### Static Mocking (Mockito 3.4+)

Sometimes you need to mock static utility classes (e.g., `UUID.randomUUID()` or `Instant.now()`). Use a `MockedStatic` block with a try-with-resources statement so it closes automatically.

Java

```
try (MockedStatic<UUID> mockedUuid = mockStatic(UUID.class)) {
    mockedUuid.when(UUID::randomUUID).thenReturn(UUID.fromString("123-abc"));
    
    // Call your service that relies on UUID.randomUUID()
    String id = myService.generateId();
    assertEquals("123-abc", id);
}
```

### @Mock vs @MockBean (Spring Boot context)

- **`@Mock`**: A pure Mockito object. Lightning fast. Use this for standard Unit Tests where you don't load the Spring Context.
    
- **`@MockBean`**: A Spring Boot testing annotation. It replaces a bean in the Spring Application Context with a mock. Use this for **Integration Tests** (`@WebMvcTest`, `@SpringBootTest`).

## 🏗️ 14. Real-World Example

Java

```
@ExtendWith(MockitoExtension.class)
class UserServiceTest {

    @Mock
    private UserRepository repo; // The dependency

    @InjectMocks
    private UserService service; // The class under test

    @Captor
    private ArgumentCaptor<User> userCaptor;

    @Test
    void shouldUpdateUserStatus() {
        // 1. Arrange (Given)
        User mockUser = new User(1L, "Umesh", "PENDING");
        when(repo.findById(1L)).thenReturn(Optional.of(mockUser));

        // 2. Act (When)
        service.activateUser(1L);

        // 3. Assert (Then)
        verify(repo).findById(1L);
        verify(repo).save(userCaptor.capture());
        
        User savedUser = userCaptor.getValue();
        assertEquals("ACTIVE", savedUser.getStatus());
    }
    
    @Test
    void shouldThrowExceptionWhenUserNotFound() {
        when(repo.findById(1L)).thenReturn(Optional.empty());

        assertThrows(EntityNotFoundException.class, () -> {
            service.activateUser(1L);
        });
        
        verify(repo, never()).save(any());
    }
}
```

## 🧠 15. Best Practices

### ✅ DO

- Mock external dependencies (DBs, APIs, Message Queues).
    
- Test **behavior**, not implementation details.
    
- Give tests meaningful names (`shouldReturnUserWhenIdExists`).
    
- Use constructor injection in your main classes (makes mocking easier).
    

### ❌ DON'T

- Don't write unit tests for simple Getters/Setters.
    
- Don't hit a real database in a unit test (use Testcontainers for Integration tests instead).
    
- Don't overuse `@Spy`. If you need a Spy, your class might be doing too much (violating Single Responsibility Principle).
    
- Don't use `reset(mock)`. It is a code smell. Just create a new test method with fresh mocks instead.

## 🎯 16. Interview Cheat Sheet

- **Mockito:** A framework to create fake objects for isolation in tests.
    
- **@Mock vs @InjectMocks:** `@Mock` creates the fake. `@InjectMocks` creates the real object and stuffs the fakes inside it.
    
- **Spy vs Mock:** Mocks are 100% fake. Spies are real objects where you can fake _some_ methods.
    
- **Argument Matchers Rule:** If you use one matcher like `any()`, you must use matchers for all arguments in that method call.
    
- **ArgumentCaptor:** Used inside `verify()` to catch the object that was passed to the mock, allowing deep assertions.
    
- **doReturn vs when:** Use `doReturn` for Spies or void methods to prevent the real code from executing. Use `when` for standard mocks.
