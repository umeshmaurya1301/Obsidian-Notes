Problem Description

Given a binary array nums, return the maximum length of a contiguous subarray with an equal number of 0 and 1.

Examples

Input: nums = [0,1]
Output: 2
Explanation: The entire array contains one 0 and one 1.

Input: nums = [0,1,0]
Output: 2
Explanation: The longest contiguous subarray with equal number of 0 and 1 is [0,1].

Input: nums = [0,0,1,1,0]
Output: 4
Explanation: The longest valid subarray is [0,0,1,1].

Constraints

1 <= nums.length <= 100000
nums[i] is either 0 or 1

Intuition

The problem asks for a subarray containing equal number of 0s and 1s.

A useful trick is:
Convert:
0 -> -1
1 -> +1

Now the problem becomes:
Find the longest subarray whose sum is 0.

Why?

Because:

Equal number of +1 and -1 gives total sum 0
That directly represents equal number of 1s and 0s

We use prefix sum to efficiently detect such subarrays.

If the same prefix sum appears again at two different indices:
prefixSum[i] == prefixSum[j]

Then:
sum(i+1 ... j) = 0

Meaning:
The subarray between them contains equal number of 0s and 1s.

Approach

Maintain:

A running prefix sum
A HashMap storing:
prefixSum -> first occurrence index

For every element:

If nums[i] == 0, subtract 1
Else add 1

If the current prefix sum has already been seen:

The subarray between previous index and current index has sum 0
Calculate its length
Update maximum length

Otherwise:

Store the first occurrence of the prefix sum

Important Initialization:

map.put(0, -1)

Physical significance of this:
It means:
"Before the array starts, the prefix sum is already 0."

This creates a virtual starting position before index 0.

Why is this needed?

Example:
nums = [0,1]

Converted:
[-1,+1]

Prefix sums:
index 0 -> -1
index 1 -> 0

At index 1, prefix sum becomes 0.
That means:
sum(0...1) = 0

To calculate length:
1 - (-1) = 2

Without storing:
0 -> -1

We would miss valid subarrays starting from index 0.

This is a very common prefix sum trick:
Initialize the neutral state before traversal begins.

Dry Run

Input:
nums = [0,1,0]

Converted:
[-1,+1,-1]

Initial:
map = {0=-1}
prefixSum = 0
maxLen = 0

i = 0
nums[0] = 0
prefixSum = -1

-1 not present
Store:
map[-1] = 0

i = 1
nums[1] = 1
prefixSum = 0

0 already present at index -1

length = 1 - (-1) = 2
maxLen = 2

i = 2
nums[2] = 0
prefixSum = -1

-1 already present at index 0

length = 2 - 0 = 2
maxLen = 2

Final Answer = 2

Edge Cases

Array length is 1
No valid subarray exists
Return 0

Entire array is balanced
Example:
[0,1,0,1]
Need map.put(0,-1) to correctly calculate full length

All elements same
Example:
[0,0,0]
No balanced subarray

Complexity

Time: O(n)

Space: O(n)

Java Code

class Solution {
    public int findMaxLength(int[] nums) {

        Map<Integer, Integer> map = new HashMap<>();

        map.put(0, -1);

        int prefixSum = 0;
        int maxLen = 0;

        for (int i = 0; i < nums.length; i++) {

            if (nums[i] == 0) {
                prefixSum -= 1;
            } else {
                prefixSum += 1;
            }

            if (map.containsKey(prefixSum)) {

                int len = i - map.get(prefixSum);
                maxLen = Math.max(maxLen, len);

            } else {
                map.put(prefixSum, i);
            }
        }

        return maxLen;
    }
}

Key Insights

Convert:
0 -> -1
1 -> +1

Equal number of 0s and 1s becomes:
Subarray sum = 0

If same prefix sum appears again:
Subarray between them has sum 0

Store only first occurrence of prefix sum to maximize subarray length

map.put(0,-1) handles subarrays starting from index 0

Patterns

Prefix Sum
HashMap
Longest Subarray with Condition
Running Balance Technique

Pitfalls

Forgetting:
map.put(0,-1)

Updating map every time instead of storing first occurrence only

Not converting 0 to -1

Using nested loops leading to O(n^2) TLE
