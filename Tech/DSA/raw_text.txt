FILE: LT_0049_GROUP_ANAGRAMS

Difficulty: Medium

Problem Description

Given an array of strings strs, group the anagrams together.

Two strings are anagrams if they contain the same characters with the same frequencies, but the order of characters may differ.

Return the grouped anagrams in any order.

Examples

Input: strs = ["eat","tea","tan","ate","nat","bat"]
Output: [["eat","tea","ate"],["tan","nat"],["bat"]]
Explanation: "eat", "tea", and "ate" are anagrams because after sorting they all become "aet". Similarly, "tan" and "nat" become "ant".

Input: strs = [""]
Output: [[""]]
Explanation: Empty string grouped as a single anagram group.

Input: strs = ["a"]
Output: [["a"]]
Explanation: Single character string forms one group.

Constraints

1 <= strs.length <= 10000
0 <= strs[i].length <= 100
strs[i] consists of lowercase English letters.

Intuition

Two strings are anagrams if their characters and frequencies are identical.

Important observation:

If two strings are sorted and become equal, then they are anagrams.

Example:

"eat" -> "aet"
"tea" -> "aet"
"ate" -> "aet"

All become the same sorted string.

So we can use the sorted string as a unique key.

The problem becomes:

Group all original strings having the same sorted representation.

Approach

Use a HashMap where:

Key:
sorted version of the string

Value:
list of strings belonging to that anagram group

Steps:

Traverse every string.
Convert string into char array.
Sort the char array.
Convert sorted array back into string.
Use sorted string as hashmap key.
Add original string into corresponding group.
Return all hashmap values.

Dry Run

Input:
strs = ["eat","tea","tan","ate","nat","bat"]

Initial:
map = {}

Iteration 1:
str = "eat"

Sort:
"eat" -> "aet"

map:
"aet" -> ["eat"]

Iteration 2:
str = "tea"

Sort:
"tea" -> "aet"

map:
"aet" -> ["eat","tea"]

Iteration 3:
str = "tan"

Sort:
"tan" -> "ant"

map:
"aet" -> ["eat","tea"]
"ant" -> ["tan"]

Iteration 4:
str = "ate"

Sort:
"ate" -> "aet"

map:
"aet" -> ["eat","tea","ate"]
"ant" -> ["tan"]

Iteration 5:
str = "nat"

Sort:
"nat" -> "ant"

map:
"aet" -> ["eat","tea","ate"]
"ant" -> ["tan","nat"]

Iteration 6:
str = "bat"

Sort:
"bat" -> "abt"

Final map:
"aet" -> ["eat","tea","ate"]
"ant" -> ["tan","nat"]
"abt" -> ["bat"]

Return:
[["eat","tea","ate"],["tan","nat"],["bat"]]

Edge Cases

Empty string
Input:
[""]

Output:
[[""]]

Single string
Input:
["abc"]

Output:
[["abc"]]

Duplicate strings
Input:
["eat","eat"]

Output:
[["eat","eat"]]

All strings unique
Every string forms its own group.
Very large input
Efficient hashmap grouping is necessary.

Complexity

Time: O(n * k log k)

Space: O(n * k)

Where:
n = number of strings
k = average string length

Sorting each string costs:
O(k log k)

Java Code

class Solution {
    public List<List<String>> groupAnagrams(String[] strs) {

        Map<String, List<String>> map = new HashMap<>();

        for(String str : strs) {

            char[] arr = str.toCharArray();

            Arrays.sort(arr);

            String key = new String(arr);

            map.putIfAbsent(key, new ArrayList<>());

            map.get(key).add(str);
        }

        return new ArrayList<>(map.values());
    }
}

Key Insights

Anagrams become identical after sorting.
Sorted string acts as canonical representation.
HashMap efficiently groups strings with same key.
Original strings are stored, not sorted strings.
Multiple strings can map to the same key.
This is a classic grouping-by-transformation problem.
Sorting simplifies anagram detection.

Alternative Optimized Approach

Instead of sorting each string, we can use character frequency count as the key.

Example:

"eat"

Frequency:
a=1
e=1
t=1

Key:
#1#0#0#0#1...

This avoids sorting and improves complexity to:

O(n * k)

The separator "#" is important to avoid ambiguity.

Example:

Without separator:
[1,11] -> "111"
[11,1] -> "111"

Collision occurs.

With separator:
[1,11] -> "#1#11"
[11,1] -> "#11#1"

Now keys remain unique.

Pitfalls

Forgetting to convert sorted char array back into String.
Using char[] directly as hashmap key will not work correctly.
Forgetting that multiple strings can belong to same group.
Not initializing list before adding values.
Forgetting separator while building frequency-based key can cause collisions.
Confusing sorted string with original string.
